# 夹笔与绘图控制窗口

```bash
cd /home/a/ArmHub
bash scripts/drawing_panel.sh
# 启动后自动尝试只读连接，仍不使能或运动
bash scripts/drawing_panel.sh --connect
# 仅查看之前的真实反馈轨迹；不会构造硬件会话
bash scripts/drawing_panel.sh --replay logs/movel/pen_square_execute_20261019
```

本机使用已有 PyQt5 与动力学环境。源文件为 `apps/drawing_panel/app.py`（Qt 窗口和等比例画布）、`controller.py`（单线程硬件拥有者与任务），沿用 `apps/movel/` 的官方 FK/IK、受限参考曲线和反馈分析。不需要浏览器服务。启动不回零、不自动开合夹爪；“允许执行实机动作”初始未勾选。

## 使用顺序

1. 接通机械臂主电源，点击“连接机械臂（只读）”，核对实时 TCP、六轴角度与夹爪位置。
2. 勾选“允许执行实机动作”。默认准备位为基座 XYZ `[240,0,100]` mm，姿态沿用此前实测通过的绘图姿态；可编辑 XYZ。“到绘图准备位”从当前反馈起点规划关节参考到该位姿，不暗中先 home。
3. 用开爪、关爪装笔。用上升/下降 1 cm 调整笔尖。升降是基座 Z 方向的笛卡尔路径，保持末端姿态；默认以图形设置的速度生成并受限重定时。
4. 在预期起笔位置和高度点击“记为绘图起点”。此按钮只记录当前新反馈，不运动。此后图形以它为首个顶点，正方形默认沿 `+X、+Y、−X、−Y` 四边。
5. 选择图形、平面、尺寸、速度；先预检，再按正向或反向画。实际参考时长在窗口显示，不保证尺寸除输入速度就是实际时长。
6. 直线正向结束在终点，反向从该终点沿原线画回来。正方形和圆都是闭合曲线，正反均从同一顶点开始。图形/尺寸改变后，如当前位置不在本方向起点，绘图会拒绝；抬笔后可明确点击“到正向/反向起点”定位，不会自动画引入线。
7. 结束后先抬笔离纸，再点“回到 Home”。此按钮是显式动作，不自动插入抬笔或返回准备位。

“保持停止”或 Esc 向唯一控制线程发取消请求，由现有后端发送当前实测位置保持并核对反馈；不是物理急停。关闭窗口也会等待同一停止/关闭流程，不让 UI 线程直接调用串口。故障、反馈超时或跟踪超限沿用后端拒绝与保持逻辑。已有任务执行时不排队新的动作。

开爪原始目标 1.6 rad，关爪目标 0 rad，动作速度 .3 rad/s、限矩 .3 Nm。关爪持续停滞时转实测位置保持，只报告可能接触物体，笔是否夹牢由操作者确认；保持动作沿用现有后端 1 Nm 夹爪力矩上限，限矩不等于已标定夹持力。

## 速度与高度

绘图速度输入 1–100 mm/s。系统检查关节速度、加速度、jerk、自碰撞和所设 TCP 最低高度，必要时延长轨迹时间。提高请求值可能仍受转角处 jerk 约束，不通过放宽限制来冒充提速。Home/准备位单独设置关节速度比例，默认 20%。

最低高度只检查模型 TCP，不是笔尖或机械臂所有零件的桌面碰撞检测。未标定工具偏移时，反馈画的是官方 SDK 的 TCP（joint6 局部 X +0.165 m）。姿态近似不变时，固定笔尖偏移不改变相对路径形状；姿态误差、笔杆挠曲与纸面接触会影响实际笔迹。这里没有接触力控制或自动找纸面。设置起点和降低高度需按现场笔尖位置确认。

## 输出和纸面比对

每次启动创建 `logs/drawing_panel/<时间>/`：

- `telemetry.csv`：连接期间持续保存六轴原始 q/dq、各电机主机接收时间、计数/故障、夹爪位置、TCP XYZ。所有值来自新反馈；CSV 不把计划值冒充反馈值。
- `NNN_<平面>_<图形>_<方向>/run.json`、`.npz`：每次绘图的参数、预检结果、状态和完整原始反馈。中断也保存已记录部分。
- 同目录 `feedback_path.png`：毫米等比例的理想路径、规划 FK、反馈 FK 叠加图；`feedback_xyz.csv`：反馈时间、绝对 XYZ（米）、相对起点 XYZ（毫米）。
- 同目录诊断 PNG、逐帧 CSV、`summary.png`、`metrics.json`：沿用原误差分析。
- `comparison/`：本窗口累计的轨迹与正反对比；只有起点、姿态、尺寸、图形、平面、圈距、请求速度一致的记录才配对。相同组取最近一次正向和反向。不同组的对比文件带几何标识后缀。

画布显示灰色理想线、黄色规划 FK、青色正向反馈、紫色反向反馈。可切 XY/XZ/YZ 投影、清空显示或另存画布 PNG。“清空画布”不删除数据；绘图完成后自动导出数据，无需另点保存。回 Home、准备位和升降动作会显示反馈轨迹并进入连续 `telemetry.csv`，不作为绘图精度实验单独计分。

比较纸面笔迹时建议记录纸上的尺寸或拍摄带标尺的正视图，和等比例轨迹图对齐。编码器 FK 仍不是外部测量；原分析器延迟搜索上限 300 ms，触界以 JSON 标识和图中的 `*` 提示。

## 验证边界

已用此前真实 4 cm 正方形记录回放并检查窗口布局。新增测试覆盖无自动引入段、反向端点一致、真实模型预检/高度拒绝、禁止未经勾选的动作、拒绝重叠命令、取消后保存半程反馈及保持确认、几何分组配对和反馈导出。原录制与执行器相关回归检查也通过。

本轮 14:30 的首次只读实机连接尝试发现电机 1–7 无反馈；此后操作者已连接并使用窗口，但尚未逐项完成 Home/准备位/升降/绘图的实机验收。既有 CLI 实机证据不等同于新窗口所有按钮的实测通过。恢复电机供电后，先核对只读反馈，再按操作顺序使用。

FK 返回的旋转/变换矩阵已按每帧独立拷贝，避免 Pinocchio 后续计算覆写历史姿态。新增回归测试检查此行为；原始关节 q 和反馈 XYZ 不受该复用问题影响，旧记录中的派生姿态误差需要重新计算后使用。

## 官方 moveJ 画圆试验

新版窗口“画圆方式”默认选 `SDK moveJ（试验）`，也可切回“原连续参考”。仅圆形使用此选项，其他动作保持原方式。更新源码后应正常关闭旧窗口再启动：

```bash
bash scripts/drawing_panel.sh --shape circle
```

圆周仍通过逐点 IK 和受限五次样条生成关节路径；执行时每个控制周期实际调用工程内官方 `Panthera.moveJ(target_q, duration=0.05, iswait=False)`。复用现有 ArmHub 会话，不构造第二个硬件 Panthera；其 `Joint_Pos_Vel` 接口由桥接器送入现有七槽发送函数，六轴与夹爪明确填写。

相对原方式的主要差异：原方式按样条导数设置固件速度上限，moveJ 按 `(本周期目标角 − 最新反馈角)/0.05` 计算。保留速度下限和每轴物理速度上限，计算速度超限时拒绝发送。参考曲线仍受位置/速度/加速度/jerk 和自碰撞检查，反馈故障、跟踪偏差、超时、夹爪保持与停止机制沿用；moveJ 根据反馈计算的速度上限不承诺具有同样的加速度/jerk 平滑性。该方式不逐点等待到位，不等同于 720 次阻塞 moveJ。

独立入口（先在界面断开串口）：

```bash
cd /home/a/ArmHub
# 需要时：从 Home 到已用过的绘图准备位。已在纸面起点则跳过。
bash scripts/move_to.sh --robot panthera_ht --backend hardware --xyz .24 0 .1 --quaternion 0 .7071067812 0 .7071067812 --velocity-scale .2 --execute
# 只读预检，不运动
bash scripts/draw_circle_movej.sh
# 当前点起画，直径 4 cm、请求速度 2 cm/s，不引入、不回 Home
bash scripts/draw_circle_movej.sh --execute
# 覆盖方向/尺寸/速度
bash scripts/draw_circle_movej.sh --direction rev --size .06 --speed .03 --execute
```

原始数据新增 `dispatched_speed_caps_rad_s`，保存实际下发的每轴速度上限；记录标签/预检/后端日志包含 `command_mode`，避免与原连续参考试验混淆。CLI Ctrl+C 或界面“保持停止”仍使用当前姿态保持。

本轮 SDK moveJ 的 5 项专用检查通过，并完成相关回归。实机尝试在接近 Home 的姿态被圆形第一段 IK 预检拒绝，未发送运动指令；用户选择自行准备位置并运行命令，尚无此模式完成画圆的实测结果。

## 圆形时间参数化提速修正

圆形改用 `apps/movel/circle_trajectory.py`：在完整圆周上取 91 个精确 IK 站点（eps=1e-8），先拟合几何关节曲线 q(u)，再复用项目已有 C3 路径进度函数生成 u(t)。速度、加速度、jerk 通过链式法则计算；启停条件来自时间曲线，不再把几何曲线在起点强行夹成零斜率。拟合后复核圆周 FK 误差和姿态，再执行原有全轨迹限位/动态/自碰撞/高度检查。

以操作者此前两个实机记录的起点进行**离线重规划**，直径 40 mm、请求平均速度 20 mm/s：正向从 166.02 s 降为 6.47 s，反向从 120.92 s 降为 6.47 s。加速度上限仍为每轴 .8 rad/s²，jerk 上限仍为每轴 4 rad/s³，没有修改硬件配置。结果和比较图见 `validation/drawing_panel/circle_timing_fixed.json/png`。6.47 s 是规划时长；实机跟踪表现尚待操作者重新测量。

GUI 和 CLI 都自动为圆形使用新时间参数化；其他图形保持原实现。`SDK moveJ（试验）` 仍然是当前圆形默认下发方式。需要正常关闭旧窗口后重开，内存中的旧代码不会热更新：

```bash
cd /home/a/ArmHub
bash scripts/drawing_panel.sh --shape circle
# CLI：合适的实际起笔位置下先预检，再执行
bash scripts/draw_circle_movej.sh
bash scripts/draw_circle_movej.sh --execute
# 完全离线复核已记录数据，不连接硬件
bash scripts/with_dynamics.sh scripts/validate_circle_timing.py logs/drawing_panel/20261019_145607_766429/comparison
```

本机导入的官方 Python SDK 确实包含“先规划，再执行”的函数链：`compute_cartesian_path → compute_time_parameterization → smooth_trajectory_spline → _execute_trajectory`。当前源码的时间参数化是简化实现，指定 duration 时均分时间；轨迹执行是在电脑端按时调用 `Joint_Pos_Vel`，不代表控制板接收并缓存完整轨迹，也不是调用真正的 MoveIt IPTP。ArmHub 当前复用官方 IK 与 SDK 发送通道，同时保留本工程的反馈/停止检查；此次只修正圆形前端时间规划。
