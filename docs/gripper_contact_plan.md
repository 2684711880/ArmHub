# 夹爪接触判断与保持：当前证据和标定入口

当前目标是让已录轨迹的夹爪能稳定夹持蓝块，不改变六轴轨迹。当前 LeRobot 数据集是位置动作与位置观测，不含夹爪力矩。

## 已核对的控制链

`lerobot_replay` 每帧调用 `get_observation` 和 `send_action`。官方正常执行分支对夹爪使用五参数命令：位置为录制的 `gripper.pos`，目标速度与前馈力矩均为零，`Kp=4.5`、`Kd=0.45`。六轴继续使用其原有增益和重力前馈。

示教动作等于实测位置。若示教夹爪恰好接触物块，重放同一开度会使静态位置误差接近零，缺乏持续夹紧力；这是源码支持的可能原因，还未测得实机回放中的位置误差与力矩，不能断言唯一原因。

原生 SDK 能返回 ID 7 的位置、速度、力矩、反馈时间与计数。电机类型是 `3536_32`，SDK含类型相关力矩换算；这里的 `torque` 是电机反馈量，不是经过夹指测力计标定的接触力。

## 最小下一步：录一次实际回放的夹爪力矩

先退出其他控制器并摆好物体。回位与回放均会运动，诊断开关不额外改变夹爪指令：

```bash
cd /home/a/ArmHub
bash scripts/lerobot.sh prepare --execute
bash scripts/lerobot.sh replay --repo-id local/blue_pick_trial_01 \
  --episode 0 --execute --gripper-log
```

CSV与摘要保存到 `logs/lerobot/gripper/replay_<时间>.csv` 及 `.csv.summary.json`。包含新请求目标、上一帧请求目标、实际开度、速度、电机反馈力矩、反馈时间与计数；本帧反馈发生在新指令之前，要结合上一帧目标对齐分析。日志不增加反馈查询、不启动第二个 SDK 控制者，不改写数据集，不改变官方夹爪增益。反馈过期/故障/无效或写盘失败则中止回放并由已有 `finally` 退出保持。

## 标定后采用的状态流

1. 开爪：按目标位置和受限速度张开。
2. 闭合：以受限速度和受限力矩向闭合方向移动；录制开度用于识别开合意图，不把接触时的实测开度当作足够的夹紧目标。
3. 疑似接触：闭合方向反馈力矩超过实测阈值，且速度持续较低，开度还未到空夹终点。要求跨多个新反馈持续成立，过滤摩擦和瞬态尖峰。
4. 保持：切换为经标定的有上限夹持策略，持续监控力矩、开度及故障。不可继续追逐过深的闭合目标。
5. 张开指令：退出夹持；异常/超时/空夹由独立分支处理，不能记为夹取成功。

阈值、空夹终点、闭合方向力矩符号、保持力矩与闭合上限要由实物日志及空夹对照确定。阈值不能照搬六轴力矩或任意示例值。单靠电机负载只能判断疑似接触，也可能是卡住；要确认物块没有滑落，还需实际小幅抬起观察或额外感知。

本次只增加诊断入口，不默认启用未经标定的自动加力或把疑似接触宣称为抓稳。现有位置数据仍可复用，后续改动位于夹爪执行层。
