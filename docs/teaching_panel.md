# 桌面抓取示教窗口

启动：

```bash
cd /home/a/ArmHub
bash scripts/teaching_panel.sh
```

窗口启动不打开相机、不连接机械臂、不使能、不回零。使用独立 `.venv_lerobot`；缺少依赖时运行 `bash scripts/setup_lerobot.sh`。无设备体验使用 `bash scripts/teaching_panel.sh --demo`，窗口明确显示 DEMO；其准备位、原始回合和训练数据与实物分别保存。

## 第一次示教

1. 点击“打开相机”，查看 D435 画面，确认工作区域和夹爪可见。相机取自 `integrations/panthera_lerobot/configs/local.json` 的 `d435` 配置。
2. 点击“连接机械臂（只读）”，核对新反馈。退出其他 ArmHub 控制器；新窗口沿用同一串口占用检查和硬件锁。
3. 核对参数，勾选“允许实机动作”。点击“进入拖动模式”，手动调整成夹爪朝下、悬空的准备姿态。此功能沿用既有官方重力模型及力矩、速度、反馈和周期保护，不自动应用新的负载辨识结果。
4. 点击“保存当前为准备位”。拖动中保存会先请求当前位置保持，确认反馈静止后再保存六轴关节角、FK 位置、姿态及来源。保存不会重新标定编码器，也不自动解算朝下姿态。
5. 显式点击“张开”，摆好物体。参数中的开度为夹爪原始电机 rad，并非毫米；闭合速度与力度上限需由实际物体确认。
6. 点击“进入拖动模式”，在准备位附近按 F5 或点击“开始录制”。手动拖动机械臂，按 C 闭合、O 张开，完成一轮抓放。编辑文本时 O/C 快捷键不触发。
7. 按 F6 或点击“结束回合”，没有回合时限和定时自动结束。结束录制后请求保持，直到新反馈确认稳定；不会自动回准备位。
8. 在“回合列表”中拖动时间轴或点击“播放记录”，查看图像和七维位置曲线。图像回看不驱动机械臂。
9. 选择“成功 · 保留到训练集”进行 LeRobot 视频数据导出；“失败 · 仅归档”和“丢弃 / 重录”均保留原始文件、排除训练集。采样异常回合不能标为训练数据。
10. 点击“预览回准备位路径”，核对报告，再点击“执行回准备位”。路径起点变化后必须重新预览；回位不改变夹爪当前开度。重新摆物体，进入拖动模式，再开始下一回合。

空格或红色“停止并保持”按钮会取消未执行的旧命令、结束当前回合并请求保持。只有新反馈满足既有稳定判据后才显示“位置保持”；失败显示未确认。它不是物理急停，也不表示电机失能。

## 界面与文件

- 实物准备位与参数：`integrations/panthera_lerobot/configs/teaching.json`。数据集、任务、FPS、夹爪目标及回位速度可编辑，准备位也可重新记录。
- 实物原始回合：`datasets/teaching_raw/hardware/<时间>/`；包含 RGB PNG、`samples.jsonl`、`episode.json`。
- 实物成功数据：`datasets/lerobot/<repo-id>/`，默认 `local/panthera_teaching`。
- 演示参数：`logs/teaching_panel/demo_settings.json`；演示原始数据和导出数据分别带 `demo` 来源、位于独立目录。
- 每帧记录六轴实测位置、夹爪实测位置，以及六轴示教位置加夹爪命令目标构成的动作。夹爪目标与实际位置分别保存，防止丢失开合意图。
- 保留图像主机接收时间、控制采样时间和电机反馈时间/计数，未宣称实现相机曝光与电机硬件时钟同步。LeRobot 导出使用固定 FPS 时间索引，实际采样间隔另存于原始数据。

回合需至少五帧，最大间隔不超过 `2.5/FPS`，平均频率偏差小于 20%，并正常结束，才可人工确认成功后导出。不自动判断抓取成功。成功与失败标签由人检查填写，模型不会自行训练或自行复位环境。

导出使用官方 `LeRobotDataset`，保存后可直接训练：

```bash
bash scripts/lerobot.sh train --repo-id local/panthera_teaching -- --steps=100
```

`100` 步仅用于验证训练入口，不代表训练完成。当前安装 CPU 版 PyTorch。正常训练的步数与效果需根据数据和测试确定。

## 控制与模型边界

窗口的一个工作线程持有现有 `PantheraHardwareBackend` 及原生官方 SDK 会话，复用反馈、硬件锁、保持及 Ruckig 参考执行器；拖动采用官方重力模型和力矩接口。没有调用另一个 `PantheraFollower.connect()` 开第二条电机控制线程。相机、图像写盘、视频编码与 UI 分别处理，写盘队列满、图像过期、反馈故障或控制超时会中断回合并请求保持。

拖动的六轴力矩命令与夹爪位置命令分别发送，遵守 SDK 整帧协议模式；禁止同帧混用。回位的夹爪保持和跟踪检查沿用既有后端。

准备位记录的是用户调整的姿态，不自动验证夹爪朝下。TCP XYZ 是模型 `gripper_center` 在 `base_link` 下的坐标；未确认桌面和夹指尖偏移时，不能把 Z 当作离桌高度。可选 TCP Z 下限只约束该模型参考点。回准备位预检含模型自碰撞，不含实际桌面、物体、线缆和外部障碍物。

新增本地补丁统一了官方数据集“创建”和“读取”的 `root` 语义，避免创建时重复拼接 repo-id。补丁和哈希记录在集成目录中，恢复固定版本源码会一并应用。

## 离线验收

```bash
bash scripts/with_lerobot.sh -m unittest discover -s tests -p 'test_teaching_panel.py' -v
# 使用一个新的输出目录，所有相机与机械臂均为合成对象：
bash scripts/with_lerobot.sh scripts/validate_teaching_panel.py --output validation/teaching_panel/my_demo_run
```


`validation/teaching_panel/acceptance.json` 记录完整合成闭环：保存准备位、拖动采集、夹爪开合目标与反馈、人工成功标签、官方视频导出、追加第二回合、重新读取解码、显式返回准备位。`validation/teaching_panel/regression.log` 保存控制保护回归结果。

以上是软件与合成数据验收。首次 D435 实际图像、拖动负载、夹爪接触和准备位实物返回仍待用户实测；本次未连接机械臂或执行实机命令。

相机短暂等帧超时会保留连接并重试，不再因单次 250 ms 超时永久关闭预览；连续 2 秒无新图像才停止并明确报错。预览底部会显示等待/关闭状态，避免旧画面仍标为实时。录制仍保留图像过期中断保护，不自动续录。修复与 D435 实测记录见 `validation/teaching_panel/camera_recovery.json`。
