# Panthera J6 相机负载：静态采集

相机固定在 link6，不拆卸。该脚本只采集数据，不修改 URDF、重力补偿参数或保护配置。位置保持时记录实测力矩，并计算原模型重力；不能用纯力矩拖动时的下发力矩代替静态负载测量。

## 用户执行

先关闭 ArmHub 面板、拖动程序及其他占用串口的控制器。让机械臂处于相机和线缆能随 J6 正反转的自由空间，采样时勿托住负载；急停可操作。

```bash
cd /home/a/ArmHub
# 只读当前位置、预览计划和模型自碰撞检查；不发送运动目标
bash scripts/collect_j6_gravity.sh
# 实际执行，以本次启动的实测位置为基准
bash scripts/collect_j6_gravity.sh --execute
```

默认 J3 相对起点偏移为 `0°、+10°、+20°`；每组 J6 相对起点扫描 `-30°…+30°`，间隔 10°，正反各一次。两端分别额外走 3°预行程，以保证端点接近方向。因此 J6 总运动范围为起点 **±33°**，并非只有 ±30°。共 42 个采样点，J3 的最后一组保留为验证集。

每点连续静止至少 0.6 秒，然后采样 2 秒、至少 20 个有效样本。速度上限 2°/s；真实采样频率由串口反馈和处理耗时决定。每次仅推进 J3 或 J6 的一个目标，最大 4°，继续调用现有 <=5° 单关节接口；其他轴始终使用固定计划保持目标，不把逐帧实测位置重新作为保持目标，以免量化/跟踪误差累积。原始零位噪声略越限时，非运动轴保持目标取固定物理边界，不重设编码器。不修改现有力矩上限，J6 为 3 Nm。总时长通常为数分钟，取决于实物到位和停稳时间。

默认参数越界时会在运动前报错，不裁剪计划、不自动更换起始姿态。可明确修改扫描方向，例如：

```bash
bash scripts/collect_j6_gravity.sh --j3-offsets-deg 0 -10 -20
bash scripts/collect_j6_gravity.sh --j3-offsets-deg 0 -10 -20 --execute
```

当前碰撞检查仅覆盖机器人名义模型的自碰撞，不包含相机、线缆和外部障碍物。启动姿态应让 J6 轴具有足够横向重力激励；脚本检查训练特征矩阵秩并报告条件数，不能仅凭点数判断参数可辨识。

归一化条件数超过 100 时提示激励偏弱，超过 1000 时拒绝运动；这是本采集脚本的工程筛选阈值，不是辨识精度保证。

结束、Ctrl+C 或异常都会尝试切到当前位置保持并确认反馈；**停在最后位置，不自动回起点或回零，也不自动断使能**。保持未确认会报错。已有固件 `motor_timeout_ms=0` 不变，不以断 USB、kill -9 代替 Ctrl+C。

## 保存的数据

终端打印唯一目录 `logs/j6_identification/<UTC时间>/`，禁止覆盖已有目录：

- `metadata.json`：起始姿态、控制参数、模型/脚本哈希、重力方向、反馈语义和预检结果。
- `plan.json`：全部采样/过渡点、正反方向与训练/验证分组。
- `samples.jsonl`：逐帧七电机位置/速度/力矩/故障/模式/计数/反馈时间，以及六轴模型力矩、link6 局部重力、拟合特征、残差、有效标志和采样阶段。
- `poses.jsonl`：各点停稳有效数据的均值、标准差、位移跨度和样本数。
- `poses.csv`：便于快速查看各点 J6 残差的摘要。
- `summary.json`：完成/中断/失败状态、已采点数、当前位置保持确认及硬件日志位置。

失败也保留已写数据，但只有 `summary.json` 的 `status=completed` 表示全部采完；退出码非零时不要当作完整实验。采集期间位置偏差、力矩达到上限95%、夹爪漂移或反馈失效会终止采集并尝试保持。

静止判断使用连续位置窗口（沿用 0.003 rad 位移阈值），原始速度仅记录作诊断，不用单帧速度门限结束采集。位置窗口发生小幅变化时，在同一姿态丢弃未完成窗口并重新等待停稳；总等待时间有上限，持续运动仍会超时报错。原始数据以 `window_id` 区分窗口，作废时记录 `discarded_window_id`；拟合应使用 `poses.jsonl` 或其 `sample_window_id` 对应的有效采样窗口。摘要记录窗口重启次数、作废样本数和原始速度峰值。

若在 J6 已转动后中断，直接再次运行默认命令会把新的当前位置当作扫描中心。可沿用上次实验的 J6 基准，避免偏移累积：

```bash
bash scripts/collect_j6_gravity.sh --j6-origin-run /home/a/ArmHub/logs/j6_identification/上次目录 --execute
```

该选项仅固定 J6 扫描基准；J3 偏移仍相对本次启动位置。程序先用当前位置检查整条路径，必要的基准对齐也按单关节小步执行，不要求用户手动回零。

当前 SDK 反馈字段为解码后的 Nm，不是新增独立力矩传感器；尚未验证物理标定。模型夹爪滑动坐标沿用中性值，实际夹爪保持不变，原始电机 rad 不当作 prismatic m。后续拟合结果表示相机与原模型误差合成的有效重力修正，不能独立解释成相机质量。

## 后续解算

令重力在 link6 坐标系中为 `(gx, gy, gz)`，J6 局部转轴为 X：

```text
y = measured_tau6 - model_G6
X = [-gz, gy, 1]
theta = [hy, hz, bias]    # hy=m*cy、hz=m*cz，单位 kg*m；bias 单位 Nm
```

先检查信号波动、正反差异、训练矩阵条件数、各点实际激励和反馈比例，再拟合；同角度正反数据可帮助评估摩擦，不能保证静摩擦完全抵消。验证用最后一组 J3，不随机拆同一姿态的连续帧造成数据泄漏。验证通过后另行接入补偿，本脚本不会自动应用结果。

## 离线验证

完整采集后可离线解算（只读日志，不导入硬件接口；不自动应用参数）：

```bash
bash scripts/with_dynamics.sh -m examples.fit_j6_gravity logs/j6_identification/采集目录名
```

输出到 `validation/j6_identification/采集目录名/`，包含中文报告 `report.md`、全部模型结果 `fit_report.json`、未启用的候选 `candidate_parameters.json`、正反配对预测 CSV 和诊断图。输出目录须不存在，防止覆盖已审查结果。脚本交叉核对原始有效窗口与摘要，再只使用训练 J3 组拟合，最后一组独立验证。

```bash
# 不构造硬件连接，仅验证模型、计划和特征激励；输出目录须不存在
bash scripts/collect_j6_gravity.sh --offline-q 0.1 0.5 0.6 -0.2 0.3 0.4
bash scripts/with_dynamics.sh -m unittest discover -s tests -p 'test_j6_collection.py' -v
```

离线测试覆盖分段单关节发送、夹爪保持、限位/碰撞拒绝、停稳采样、力矩限幅附近拒绝、故障/陈旧反馈拒绝、持续位置变化超时、小幅位置漂移后窗口重采、中断后保留数据与保持，以及已知附加质量的特征与 Pinocchio 计算一致。另用首次失败日志的30帧反馈回放，复现并验证单帧 J4 速度尖峰不再中断采集。替身驱动测试不证明真实采集或补偿精度。
